# 03 溝通

## 規則

### 什麼時候發訊息

1. **只在三種情況發跨 session 訊息**：gate 完成的一份 TASK REPORT、卡住需要決定、要對方立刻改變行動。總監發工單、裁決、回答對方的問題，也屬於第三種。
2. **不回 ACK**：不發「收到」「開始了」「做完一半」。收到指示就做，做完在檔案和 gate 報告裡交代。對方寫「不用回覆」就真的不回。
3. **一次完整**：給同一個人的指令、裁決、補充，想清楚後合併成一則。事後要更正，等下一則必要訊息一起帶；只有會造成錯誤動作的更正才立刻單獨發。
4. **狀態寫檔**：進度寫在自己的 `RESUME_STATE.md`、排程看板、工單進度。總監和總管定時讀檔。
5. **等別人做完**：環境若有「對方閒置時通知我」這類不叫醒對方的機制（例如 `notify_when_idle`），就用它；沒有就用背景程序等某個檔案出現。不要發「做完了嗎」。
6. 同一件事要通知多人時，寫進共用檔案一次（規則檔或看板 `NOTICE`），不要逐一發訊息。
7. 訊息首行一句話說明是什麼；內容附檔案路徑，讓收件者自己讀檔，不要把長內容貼進訊息。

### PO 的訊息不漏讀

PO 的訊息有三個來源，總監每一個都讀，而且優先於 worker 訊息：
1. **每一輪的第一個動作**（不論被誰、被什麼喚醒）：讀待決頁上 PO 已回覆的項目和新留言，同一輪處理：執行或轉給負責的 worker，寫結果、關閉項目。不准「下一輪再處理」。
2. **聊天裡的 PO 訊息**（包括工作中途插進來的）：同一輪先處理，再繼續原工作；同一輪登記進 `DECISION_REGISTER.md`；會改變做法的，同一輪寫進規則。
3. **PO 動作項**：PO 說「做好了」，就視同完成，立刻通知相關 worker。
- 每輪結束前自查三件事：待決頁已讀、本輪 PO 訊息都已處理並登記、沒有「已回覆卻沒關閉」的項目。
- 處理晚了照實寫：幾點才讀到、晚了多久。
- 總監提出的待決項目如果已經不需要，主動撤回並寫原因，不讓舊題一直掛著。
- 有總管時，總管在例行排程時順便查一次：已回覆超過 10 分鐘還沒關閉的，通知總監。

### PO 待決頁

- 所有要 PO 回覆、確認或動手的事，一律先放上待決頁，聊天裡只說一句「待決頁新增了 OD-xx」。順序不能反，也不能只寫在聊天裡。
- 一筆一項，格式照 `templates/PO_PENDING.md`（ID、STATUS open / answered / closed、問題、選項、建議、PO 回覆、處理結果）。
- 要 PO 在某個 worker 的對話裡回覆時，ACT 寫明「請到『某某』對話回一句：……」，附可以直接照抄的句子。
- Worker 需要 PO 的任何東西，先發訊息給總監，標題 `PO_REPLY_NEEDED`：問題、選項、建議、影響、圖片路徑。只在自己的對話問 PO、沒報總監，視為違規。

### 回報給 PO

- 用 PO 指定的語言，先結論。只寫結論、要 PO 做的事、還沒驗證的事；細節放檔案。
- Worker 不把同一份內容再傳給 PO，除非總監要求。
- 時間戳一律讀系統時鐘（`date`），不估計。

## 為什麼

- 聊天裡的問題會被大量訊息洗掉。原專案 PO 已回覆的決定，曾經晚了 40 分鐘到 1.5 小時才被處理，所以改成「每輪第一個動作就讀待決頁」。
- 其他理由見 docs/10。
