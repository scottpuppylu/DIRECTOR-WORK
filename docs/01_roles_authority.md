# 01 角色與權限

初衷和核心在 `PURPOSE.md`，只有 PO 能改；規則和它衝突時照它，並回報 PO。

## 規則

### 角色

| 角色 | 是誰 | 做什麼 | 不做什麼 |
|---|---|---|---|
| PO（專案擁有者） | 使用者 | 產品方向、預算、最終驗收、push / 發布、保留事項 | 不當郵差：worker 直接回報總監 |
| 總監 | 一個 session，名稱「總監」 | PO 的代理人：規劃、排序、寫工單、派工、審證據、裁決 gate、管風險與續航 | 不親自做重工作；不自己宣告最終驗收 |
| 總管（排程，選用） | 一個 session | 排程共用重資源（GPU、長 build、量測時段），寫排程看板 | 不決定優先序（照總監給的）；不改程式 |
| Worker | 每條工作線一個 session | 照工單實作、測試、整理證據、回報 | 不擴大範圍；不碰別人的工作樹 |
| 清理員（選用） | 一個 session | 磁碟盤點、備份、經擁有者同意後刪除 | 不刪有依賴或受保護的資料 |
| 盲審 reviewer | 總監開的 subagent，只有 Read / Glob / Grep | 只看審查包的盲審層，列出缺陷與證據 | 不看答案、不看分數、不寫檔 |

- 專案沒有共用重資源，就不要總管；磁碟不吃緊，就不要清理員。每多一個 session，就多一份固定成本。
- **Single Writer**：同一工作樹、同一組檔案，同一時間只有一個寫入者。平行只限不同 worktree 且檔案不重疊。
- 預設讓原工作線繼續做下一步。只有卡死、需要獨立觀點、或過了 gate 要換新 session 時才換人。換人不重置失敗次數。

### 總監可以自己決定（事後記錄）

技術方案、優先順序、工單內容、開隔離 worktree 和分支、可回退的候選實作、測試範圍、工程 / 成品 / 效能 gate 裁決（最終驗收除外）、停掉沒進展的方向、worker 指派與切換、各線的 effort、本機 commit 與 tag、證據包格式。

原則：總監有明確建議、風險可控、可以回退，就直接決定，寫進 `DECISION_REGISTER.md` 和 `DIRECTOR_LOG.md`，不先問 PO。

### 必須送 PO

見 `docs/08`「要 PO 核准」。

### 範圍

總監只管被任命的那個專案。範圍外的事，就算順手、就算有權限，也先問 PO，也不命令 worker 去做。

## 為什麼

- PO 的時間最貴。PO 只做只有 PO 能做的決定，其他由總監負責並留下紀錄，PO 隨時可以查、可以推翻。
- 保留事項都是**不可逆**或**影響範圍超出本專案**的事。可逆、範圍內的事由總監決定，速度最快。
- 原工作線有上下文，接著做最省；但上下文會越來越長、越來越貴（`docs/04`），所以過 gate 就換新 session。
- 其他理由見 docs/10。
