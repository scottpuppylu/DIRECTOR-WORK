# 09 記憶索引

## 規則

1. **記憶索引（例如 `MEMORY.md`）每輪都會載入，保持在 3k token 以內**（原專案約 6 KB）。用 `tools/memory_size_check.py` 檢查，超過 exit 1。
2. 索引一行一條：`- [標題](檔名.md) — 一句話`。細節寫在個別記憶檔，不寫在索引。
3. 結案和歷史條目移到 `ARCHIVE_INDEX.md`（同一個記憶資料夾，**每輪不載入**）。索引裡留一行指向它。
4. **記憶檔本身不刪。** 只移動索引裡的那一行。
5. **進行中的不能洗掉**：「進行中」區塊的條目，要等工單結案（`DIRECTOR_STATE` 或工單寫 CLOSED）才能移進封存。
6. **規則類條目（使用者回饋、工作方式）永遠留在索引。**
7. 重複的條目合併成一行，指向主要那一份。
8. 移動前先把整份索引備份到 `DIRECTOR/SNAPSHOT/`（檔名帶日期）。
9. **何時整理**：每週一次（例如額度重置恢復時）；索引超過門檻時；新增大量條目之後。
10. 整理後再跑一次大小檢查和 `tools/context_probe.py`，確認記憶檔的 token 真的下降。

## 為什麼

- 記憶索引是固定成本，每一次呼叫都付。原專案的索引一度 8.4k token，整理到 2.5k，記憶檔總計從 12.3k 降到約 6.5k，一個檔都沒刪。
- 進行中的條目一旦移走，恢復的 session 就看不到它，等於遺失進度。
- 規則類條目決定 session 的行為；移走它，同樣的錯就會再犯。
- 先備份，整理錯了可以還原。
